# SRRT ไข้เลือดออก — แจ้งเตือนเมื่อแพทย์วินิจฉัย A90/A91 (รพ.วังน้ำเขียว)

> **เวอร์ชัน 1.5.1** — ใช้กับโรงพยาบาลที่ใช้ HOSxP · ติดตั้ง: [INSTALL.md](INSTALL.md) (**อ่านข้อ 0 "ก่อนนำไปใช้" ก่อน**) ·
> ค่าตั้งทั้งหมด: [.env.example](.env.example) · การเปลี่ยนแปลง: [CHANGELOG.md](CHANGELOG.md) · สัญญาอนุญาต: [MIT](LICENSE)

เมื่อแพทย์ลงวินิจฉัยไข้เลือดออก (ICD-10 A90/A91) ใน HOSxP แอปนี้ส่งแจ้งเตือนเข้ากลุ่ม LINE ของทีม SRRT ผ่าน MOPH Notify (หมอพร้อม)
ภายในไม่กี่นาที พร้อมลิงก์ให้ทีมเปิดดูรายละเอียดผู้ป่วย ปักหมุดบ้านบนแผนที่ เห็นวงรัศมี 100 เมตร
และได้รับแจ้งเมื่อมีผู้ป่วยรวมกลุ่ม (cluster) — แอป**อ่าน HOSxP อย่างเดียว ไม่เขียนอะไรลง HOSxP** และมีฐาน SQLite ของตัวเอง

> แอปนี้เป็นเครื่องมือช่วยแจ้งเตือน ไม่ใช่ระบบรายงานโรคทางการ (506) และไม่แทนที่ระบบเดิมของ รพ.
> HOSxP ของแต่ละ รพ. ตั้งรหัสไม่เหมือนกัน ต้องตรวจข้อมูลก่อนใช้จริง (INSTALL.md ข้อ 0) · โปรแกรมให้ตามสภาพ ไม่มีการรับประกัน

## ความสามารถ

- **ตรวจจับ** วินิจฉัย A90/A91 ทั้ง OPD (`ovstdiag`) และ IPD (`iptdiag`) ทุก 2 นาที (ตั้งค่าได้) อ่านอย่างเดียว ตั้งรหัสโรคด้วย env ได้
  นับเฉพาะรายที่วินิจฉัยตั้งแต่วัน go-live (`DENGUE_START_FROM`) กันแจ้งข้อมูลย้อนหลังท่วมกลุ่ม
- **แจ้ง LINE** ด้วย Flex Message ครั้งเดียวต่อเคส (เคสใหม่ · cluster · ยกเลิกเมื่อแพทย์แก้รหัสวินิจฉัย · คืนสถานะเมื่อรหัสกลับมา) ส่งซ้ำอัตโนมัติเมื่อส่งไม่สำเร็จ
  — **ไม่มีชื่อ เบอร์โทร หรือ HN ในข้อความ** มีเพียงตำบล/หมู่ อายุ เพศ รหัสโรค และลิงก์
- **ยกเลิก/คืนสถานะเคส** แพทย์ลบรหัสโรค → **ยกเลิกเมื่อรหัสหายไปติดกัน 3 รอบ** (กัน HOSxP ตอบว่าง/ไม่ครบชั่วคราว) ตรวจเฉพาะเคสที่วินิจฉัยภายใน
  `DENGUE_CANCEL_CHECK_DAYS` วัน (ค่าเริ่มต้น 90) · ถ้าจะยกเลิกจำนวนมากผิดปกติ (≥ 2 เคสและเกินครึ่ง) จะไม่ยกเลิกและ `/healthz` แจ้ง `last_error` ·
  รหัสกลับมาภายหลัง = **คืนสถานะอัตโนมัติ** (หมุดคงเดิม) พร้อมข้อความ "คืนสถานะเคสไข้เลือดออก" ครั้งเดียวต่อเคส
- **ป้ายในเขต/นอกเขต** ระดับอำเภอ แจ้งทุกราย ติดป้ายนอกเขตให้
- **หน้าเคส** แผนที่ Leaflet หมุดลากได้ ปุ่ม "ใช้ตำแหน่งปัจจุบัน" ปุ่มยืนยัน วงรัศมี 100 ม. (เส้นประ = ประมาณ เส้นทึบ = ยืนยันแล้ว)
  รายชื่อผู้ป่วยอื่นในวง ชื่อ/เบอร์/ที่อยู่ดึงสดจาก HOSxP ตอนเปิดหน้า (ไม่คัดลอกเก็บ)
- **พิกัดเริ่มต้น** เดาจากจุดกลางหมู่บ้าน (`village_gis_location`) หรือหมุดที่เคยยืนยันของบ้านเลขที่/HN เดียวกัน ให้ SRRT ยืนยันหรือแก้
  เคสที่ยังไม่มีพิกัดเป็น "รอปักหมุด" · ทุกการปักหมุดมี audit log
- **cluster** ≥ 2 ราย ใน 14 วัน รัศมี 100 ม. (ตั้งค่าได้) นับเฉพาะหมุดที่ยืนยันแล้ว แจ้งครั้งเดียวต่อกลุ่ม และแจ้งอัปเดตเมื่อกลุ่มโต
- **แผนที่รวม** `/map` หมุดทุกเคสในช่วงวันที่เลือก ไฮไลต์ cluster · **รายการเคส** `/` กรองตามวันที่ สถานะ ในเขต/นอกเขต
- **เปรียบเทียบปี พ.ศ.** `/trend` (v1.2.0 · เปลี่ยนเป็นปีปฏิทินใน v1.5.1) เลือกปี พ.ศ. (ม.ค.–ธ.ค.) เทียบกับ 2–3 ปีย้อนหลัง: กราฟรายเดือนซ้อนกัน · เกณฑ์ระบาด (มัธยฐาน และค่าเฉลี่ย+2SD ของปีย้อนหลัง — เกณฑ์จาก 2 ปีเป็น "เกณฑ์หยาบ") · ตารางตำบล→หมู่บ้าน · สวิตช์รวมผู้ป่วยนอกอำเภอ ·
  นับ "ราย" ตามกฎเดียวกับแจ้งเตือน (มาซ้ำใน 21 วัน = รายเดียว) จากข้อมูลย้อนหลังใน HOSxP โดยตรง เก็บเฉพาะจำนวนนับ ดู INSTALL.md ข้อ 12
- **เส้นขอบอำเภอและการระบาดปีก่อนบนแผนที่** (v1.3.0) `/map` วาดขอบเขตอำเภอ (ไฟล์ `boundaries/<รหัส>.geojson` จาก OpenStreetMap ดึงด้วย `deploy/fetch_boundary.py`) และมีปุ่มดูการระบาดปี พ.ศ. ก่อนหน้า 3 ปี เป็นวงกลมต่อหมู่บ้านที่จุดกลางหมู่บ้าน (ไม่มีจุดรายคน) ·
  หมู่บ้านที่ไม่มีจุดกลางใน `village_gis_location` ไม่ถูกวาด (แสดงเป็นสรุปจำนวน) ดู INSTALL.md ข้อ 13
- **ตำบลแยกสีและหมุด รพ./รพ.สต.** (v1.4.0) `/map` ระบายสีตำบลพร้อมป้ายชื่อ (ไฟล์ `boundaries/<รหัส>.tambon.geojson` สร้างด้วย `deploy/make_tambon_boundary.py`) และปักหมุด รพ./รพ.สต. ของอำเภอ (รายชื่อจาก `hospcode` ของ HOSxP พิกัดนำเข้าจาก CSV ด้วย `python run.py import-facilities`) · `admin` ลาก/วางหมุดเองบนแผนที่ได้ · ดู INSTALL.md ข้อ 14
- **หลายโรคและแท็บเลือกโรค** (v1.5.0) ติดตาม 7 โรคในระบบเดียว (ไข้เลือดออก เล็ปโตสไปโรสิส มาลาเรีย ชิคุนกุนยา มือเท้าปาก สุกใส อุจจาระร่วง) · กลุ่มแรกแจ้งทุกรายพร้อมหมุด กลุ่มเด็ก/อุจจาระร่วงแจ้งเฉพาะเมื่อเป็นกลุ่มก้อนในหมู่บ้านเดียวกัน · แท็บเลือกโรคด้านขวากรองรายการเคส/แผนที่/เปรียบเทียบปีงบ · เปิดโรคที่ `/settings` (`DENGUE_DISEASES`) ค่าเริ่มต้นเปิดเฉพาะไข้เลือดออก · เกณฑ์ตั้งต้นของโรคใหม่ให้ทีม SRRT ทวนก่อนใช้ — ดู INSTALL.md ข้อ 15
- **ผู้ใช้ 3 บทบาท** เรียงสิทธิ์ `viewer < srrt < admin`: `viewer` (ผู้ดู ดูอย่างเดียว) · `srrt` (ปักหมุด/แก้หมุด) · `admin` (ผู้ดูแล ทำได้ทุกอย่างของ `srrt` และเข้าหน้า `/settings`) · จำกัดการเดารหัสผ่าน · รหัสผ่านเก็บเป็น PBKDF2-SHA256 (อย่างน้อย 10 ตัวอักษร) · จัดการบัญชีด้วย `run.py add-user` / `set-password` / `remove-user` (ลบบัญชี/ลดสิทธิ์มีผลทันที — ตรวจกับฐานทุกคำขอ)
- **หน้าตั้งค่า `/settings`** (v1.1.0 — เฉพาะ `admin` จาก LAN) ตั้งฐานข้อมูล HOSxP กุญแจ MOPH วัน go-live (`DENGUE_START_FROM`) ลิงก์ (`DENGUE_BASE_URL`) และ "ยืนยันตัวเลข" (`DENGUE_DATA_AUDITED`) จากเว็บ มีปุ่มทดสอบ HOSxP (อ่านอย่างเดียว) / MOPH (เครือข่ายและรูปแบบกุญแจ) / ส่งข้อความทดสอบเข้ากลุ่ม · ค่าจากหน้าเว็บอยู่ใน `data/settings.json` และ**ชนะ `.env`** ·
  ต้องพิมพ์รหัสผ่านของตัวเองซ้ำก่อนบันทึก · เปลี่ยนโฮสต์/พอร์ต/ผู้ใช้ฐานข้อมูลต้องพิมพ์รหัสผ่านฐานข้อมูลใหม่ในคราวเดียวกัน · บันทึกแล้วแอปเริ่มใหม่เองใต้ gunicorn (ตรวจจริงตาม INSTALL.md ข้อ 11.5) · ย้อนกลับค่าก่อนหน้าได้หนึ่งชุด ·
  **ข้อควรรู้:** `settings.json` เก็บรหัสผ่านและกุญแจเป็นข้อความธรรมดา (ป้องกันด้วยสิทธิ์ไฟล์ 600 เท่านั้น) และ `run.py backup` ไม่รวมไฟล์นี้ — อ่าน INSTALL.md ข้อ 11 ก่อนใช้
- **สำรองข้อมูล** `python run.py backup [--keep N]` สำรอง SQLite ของแอปด้วย sqlite3 backup API (ตั้ง cron รายวันได้ — INSTALL.md ข้อ 10) · ไม่รวม `settings.json`
- **ตรวจก่อนใช้** `setup_check.py` + หน้า `/check` (Data Audit เฉพาะ LAN) + แถบเตือนจนกว่าตั้ง `DENGUE_DATA_AUDITED=1`
- `run.py --once --dry-run` พิมพ์ข้อความ Flex แทนการส่ง ใช้ฐานชั่วคราว ไว้ทดลองคู่กับแจ้งเตือน 506 เดิม
- **เมื่อส่ง LINE ไม่สำเร็จ** หน้ารายการเคสและแผนที่แสดงแถบส้ม "ส่ง LINE ไม่สำเร็จ N รายการ" (ระบบลองซ้ำเอง แถบหายเมื่อส่งสำเร็จ) และแถบแดง "หยุดส่งแล้ว N รายการ" (ล้มเหลวครบ 20 ครั้ง — **ไม่หายเอง** แก้ต้นเหตุแล้วรัน `python run.py rearm-alerts`; ข้อความเก่าที่ส่งซ้ำจะเป็นข้อความใหม่ และยังไม่มีการปิดทีละรายการ) · `/healthz` มี `alerts_failing` / `alerts_given_up` / `scheduler_expected` / `settings_error` / `boot_id` (รหัสสุ่มต่อโปรเซส ใช้ตรวจว่าเริ่มระบบใหม่) และ `ok` เป็น `false` เมื่อมี `last_error` มี `settings_error` มีรายการที่หยุดส่งแล้ว หรือตัวตั้งเวลาไม่มีรอบนานเกิน 3 × `DENGUE_POLL_SECONDS` (ไม่มีจำนวนเคสบน `/healthz`; ตัวอย่าง watchdog ใน INSTALL.md ข้อ 8)

## เริ่มอย่างเร็ว (เครื่องพัฒนา / ทดลอง)

ต้องใช้ Python 3.10 ขึ้นไป

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt            # Windows: .venv\Scripts\pip
cp .env.example .env                                 # แทนค่า <...> (SECRET_KEY, DB_*, DENGUE_START_FROM ...)
python setup_check.py                                # ตรวจสภาพแวดล้อม ✔ / ⚠ / ✘
python run.py add-user <ชื่อผู้ใช้> admin             # สร้างผู้ดูแล (เข้า /settings ได้) — บทบาท: admin | srrt | viewer (ถามรหัสผ่านทางแป้นพิมพ์)
python run.py add-user <ชื่อผู้ใช้> srrt              # ผู้ใช้ที่ปักหมุดได้
python run.py --once --dry-run                       # ลองหนึ่งรอบ พิมพ์ข้อความแทนการส่ง
python run.py set-password <ชื่อผู้ใช้>               # เปลี่ยนรหัสผ่าน · python run.py remove-user <ชื่อผู้ใช้>  # ลบผู้ใช้ (ถามยืนยัน)
python run.py backup --keep 14                       # สำรองฐานข้อมูลแอปไป data/backups/ (เก็บ 14 ชุดล่าสุด)
python run.py rearm-alerts                           # ให้ลองส่ง LINE ใหม่กับรายการที่หยุดส่งแล้ว (ถามยืนยัน)
```

`python run.py` และ `python setup_check.py` โหลด `./.env` ให้เอง (หรือไฟล์ที่ระบุด้วย `DENGUE_ENV_FILE`) ด้วยตัวอ่านที่ไม่รันคำสั่งและไม่ขยายตัวแปร
— ค่าที่มีอักขระพิเศษให้ครอบด้วย single quote (single quote ในตัวค่าไม่รองรับ) · `SECRET_KEY` ที่ว่าง สั้นกว่า 16 ตัวอักษร หรือยังเป็น `<...>` ทำให้แอปไม่เริ่ม
· กุญแจ MOPH ที่ยังเป็น `<...>` ถือว่ายังไม่ได้ตั้ง · ตรวจก่อนรัน: `grep -nE '^[A-Z_]+=<' .env` ต้องไม่พิมพ์อะไรออกมา (INSTALL.md ข้อ 4.4)
ติดตั้งใหม่: ใส่ใน `.env` แค่ `SECRET_KEY` → สร้างบัญชี `admin` → เปิด `http://<ที่อยู่ LAN>:6800/settings` ตั้งฐานข้อมูล / MOPH / วัน go-live (ค่าอื่นยังตั้งใน `.env` ได้เหมือนเดิม)
ติดตั้งจริงบนเซิร์ฟเวอร์และตั้งค่า MOPH Notify: [INSTALL.md](INSTALL.md)

เทสต์ (ต้องใช้ `requirements-dev.txt`): `python -m pytest`

## Deployment

รันด้วย gunicorn ผ่าน systemd — ไฟล์พร้อมใช้อยู่ใน `deploy/`:

```
gunicorn --workers 1 --worker-class gthread --threads 4 --timeout 120 --bind 0.0.0.0:6800 wsgi:app
```

**กฎบังคับ: `--workers 1` (ใช้ `--worker-class gthread --threads 4` เพื่อให้ตัวตั้งเวลาที่ช้าไม่ทำให้เว็บค้าง) และห้ามใช้ `--preload`** — ตัวตั้งเวลาตรวจจับเป็นเธรดในโปรเซสเว็บ ล็อกกันรันซ้ำและ `CYCLE_STATE`
เป็นของแต่ละโปรเซส (หลาย worker = มีตัวเดียวที่ตรวจจับ ตัวอื่นรายงาน `/healthz` ผิด) · `--timeout 120` เพราะหน้า `/check` อาจตรวจนาน

| ไฟล์ | หน้าที่ |
|---|---|
| `deploy/wnk-dengue.service` | systemd unit (ผู้ใช้ `dengue` ไม่ใช้ root, `EnvironmentFile`, hardening) |
| `deploy/ssl-dengue.conf.snippet` | บล็อก Apache ProxyPass แบบ sub-path `/dengue/` พร้อมขั้นตอน backup → `httpd -t` → reload |
| `deploy/set_env.py` | ตัวช่วยตั้ง `.env` ในเทอร์มินัล (ทางเลือกเมื่อเปิดหน้า `/settings` ไม่ได้) |

`/check` และ `/settings` เปิดได้เฉพาะ LAN ผ่านที่อยู่ตรง `http://<ที่อยู่เซิร์ฟเวอร์>:6800/check` — ทางสาธารณะ (`/dengue/check`, `/dengue/settings`) ตอบ 403 โดยตั้งใจ

**การเปิดพอร์ต:** unit ตั้ง `--bind 0.0.0.0:6800` เพื่อให้ LAN เข้าได้ **พอร์ต 6800 ต้องถูกปิดจากอินเทอร์เน็ตที่ firewall/NAT เสมอ** (แอปเชื่อรายการท้ายสุดของ `X-Forwarded-For` ตัดสินว่าเป็น LAN ผู้ที่ต่อ :6800 ตรงปลอมหัวนี้ได้ — รวมถึงเข้า `/settings` ที่แก้รหัสผ่านฐานข้อมูลได้) · ถ้าไม่ต้องเปิด `/check` และ `/settings` จากเครื่องอื่นใน LAN ให้ใช้ `--bind 127.0.0.1:6800` — จะเข้าได้ผ่าน SSH tunnel เท่านั้น (INSTALL.md ข้อ 4.7)

## สถาปัตยกรรม

แอป Flask เดียว: เธรดตั้งเวลาในโปรเซสเว็บวนทุก `DENGUE_POLL_SECONDS` — อ่านวินิจฉัยใหม่จาก HOSxP (อ่านอย่างเดียว ตั้ง `READ ONLY` ทุกการเชื่อมต่อ)
→ สร้างเคสและหมุดเริ่มต้นลง SQLite ของแอป → ส่งข้อความที่ค้างผ่าน MOPH Notify → ประเมิน cluster จากหมุดที่ยืนยันแล้ว
ผู้ใช้เปิดเว็บผ่านลิงก์ใน LINE เพื่อปักหมุด ซึ่งดึงชื่อ/เบอร์/ที่อยู่สดจาก HOSxP ตอนเปิดหน้าเท่านั้น ฐานของแอปเก็บเฉพาะคีย์ รหัสโรค วันเวลา รหัสหมู่บ้าน เพศ อายุ และพิกัด


| ไฟล์ | หน้าที่ |
|---|---|
| `wsgi.py` | จุดเข้า gunicorn (`wsgi:app`) สร้างแอปและเริ่มตัวตั้งเวลา |
| `wiring.py` | ประกอบส่วนจริง: ตั้งค่า → ฐานแอป → ตัวอ่าน HOSxP → ตัวส่ง MOPH |
| `config.py` | อ่านค่าตั้งจาก env (`Settings`) |
| `app.py`, `auth.py` | Flask app, login, จำกัดการเดารหัส, `PrefixMiddleware`, `/healthz`, ตัวช่วยสิทธิ์ (LAN เท่านั้น / บทบาท `viewer < srrt < admin` / CSRF header) |
| `case_views.py`, `map_views.py`, `check_views.py` | หน้าเคสและ API ปักหมุด · แผนที่รวม · หน้า `/check` |
| `detector.py` | ตรวจจับเคสใหม่ เคสมาตามอาการ เคสที่รหัสหายติดกัน 3 รอบ (ยกเลิก) และคืนสถานะเมื่อรหัสกลับมา |
| `scheduler.py` | เธรดตั้งเวลา ล็อกกันรันซ้ำ และรอบ `cycle_once` |
| `alerts.py`, `flexmsg.py`, `moph_notify.py` | ส่งแจ้งเตือน cluster/ส่งซ้ำ · สร้าง Flex Message · เรียก MOPH Notify |
| `hosxp.py` | ตัวอ่าน HOSxP แบบอ่านอย่างเดียว (SQL ทั้งหมด) |
| `diseases.py` | ทะเบียนโรคที่ติดตาม (7 โรค: รหัส ICD สี โหมดแจ้งเตือน เกณฑ์ตั้งต้น) และกฎต่อโรค |
| `disease_views.py` | โรคที่เลือก (`?d=`) และแท็บเลือกโรค |
| `geo.py` | รหัสหมู่บ้าน ระยะ haversine การจัดกลุ่ม cluster (ตามหมุดและตามหมู่บ้าน) |
| `store.py` | ฐาน SQLite ของแอป (เคส หมุด ประวัติแจ้ง ผู้ใช้ audit log) |
| `webfmt.py`, `templates/`, `static/` | จัดรูปแบบวันที่ไทย/ป้าย · หน้าเว็บ · Leaflet และฟอนต์ที่เก็บไว้ในแอป |
| `settings_store.py` | ที่เก็บค่าตั้งจากหน้า `/settings`: ตัวแปรที่อนุญาต 10 ตัว + ตัวตรวจค่า, อ่าน/เขียน `data/settings.json` แบบ atomic สิทธิ์ 600, สำเนา `.prev`, `effective_env` (`.env` ถูกซ้อนทับด้วยไฟล์นี้) |
| `settings_views.py` | เส้นทาง `/settings` และ `/api/settings/{save,revert,test,send-test}` — เฉพาะ `admin` + LAN, ใส่รหัสผ่านซ้ำ, ตัวจำกัดความถี่, สั่งเริ่มระบบใหม่ |
| `settings_checks.py` | ขั้นตอนของปุ่มทดสอบ HOSxP / MOPH / ส่งข้อความทดสอบ (ผลเป็นรหัสข้อผิดพลาด ไม่มีข้อความดิบ) |
| `templates/settings.html`, `static/settings.js`, `static/settings_logic.js` | ฟอร์มหน้าตั้งค่า (สร้างด้วย `textContent` ไม่ใช้ `innerHTML`) · ตรรกะล้วน (เลือกช่องที่ส่ง แปลผล ตรวจ `boot_id`) แยกเป็น `settings_logic.js` เพื่อทดสอบด้วย node |
| `setup_check.py` | ตรวจสภาพแวดล้อมก่อนใช้ (ใช้ซ้ำในหน้า `/check`) |
| `run.py` | คำสั่ง `--once`, `--once --dry-run`, `add-user <ชื่อผู้ใช้> <admin\|srrt\|viewer>`, `set-password`, `remove-user`, `backup`, `rearm-alerts` |

## ความเป็นส่วนตัว

- ชื่อ เบอร์โทร ที่อยู่ของผู้ป่วยไม่ถูกเก็บในฐานของแอป และไม่อยู่ในข้อความ LINE
- ไม่ส่งที่อยู่ไปบริการ geocode ภายนอก · tile แผนที่ขอจากผู้ให้บริการโดยเบราว์เซอร์ของผู้ใช้ (เห็นเฉพาะพื้นที่ที่ดู) หรือใช้ tile server ภายในผ่าน `DENGUE_TILE_URL`
- ข้อมูลเต็มดู INSTALL.md ข้อ 7 · ไฟล์ `data/settings.json` (และ `.env`) มีรหัสผ่านฐานข้อมูล/กุญแจ MOPH — ห้ามแนบในรายงานปัญหาหรือแชท
